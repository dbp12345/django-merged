# Примеры использования системы автоматизации

## Реальные модели в проекте

В проекте используются следующие модели:
- `company.Employees` - сотрудники
- `company.Company` - компании
- `company.Employees_Parameters` - параметры сотрудников
- `dispatch.Dispatch` - диспетчеризация
- И другие модели

## Пример 1: Автоматическое обновление статуса при изменении email

**Настройка автоматизации:**
- **Название:** "Обновление статуса при смене email"
- **Модель триггера:** `company.Employees`
- **Поле триггера:** `email`
- **Тип триггера:** `field_changed`
- **Тип действия:** `code`
- **Код действия:**
```python
# Когда email меняется, устанавливаем статус "In Progress"
if new_value and new_value != old_value:
    instance.status_code = 1  # StatusCode.IN_PROGRESS
```

## Доступные переменные в коде действия

При выполнении кода действия доступны следующие переменные:

- `instance` - экземпляр модели, который вызвал автоматизацию
- `old_value` - старое значение поля (None для новых записей)
- `new_value` - новое значение поля
- `date` - модуль date из datetime
- `datetime` - модуль datetime
- `models` - django.db.models для работы с моделями Django

## Важные замечания

1. **Название модели** должно быть в формате `app_label.ModelName` (например, `company.Employees`)
2. **Название поля** должно точно совпадать с названием поля в модели
3. **Код выполняется** с полным доступом к экземпляру модели
4. **Все изменения** автоматически сохраняются после выполнения кода
5. **Ошибки** логируются в AutomationLog для отладки
