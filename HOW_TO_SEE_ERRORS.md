# Как видеть ошибки из Docker в Cursor

## Проблема

Если Django запущен через `docker-compose up`, ошибки идут в логи docker-compose, а не в терминал внутри контейнера.

## Решение (простой способ из коробки)

### Вариант 1: Запуск Django напрямую в терминале

1. **Убедитесь, что контейнеры запущены** (только БД и Redis):
   ```bash
   cd docker
   docker-compose -f docker-compose.yml -f docker-compose.dev.yml up -d db redis
   ```

2. **В терминале внутри контейнера запустите Django:**
   ```bash
   python manage.py runserver 0.0.0.0:8000
   ```

3. **Ошибки будут видны прямо в терминале** и автоматически кликабельны!

   Когда появится ошибка:
   ```
   File "/app/core/admin_panel/admin/EmployeesAdmin.py", line 382, in EmergencyContactInline
   ```
   
   Просто **кликните на путь** `/app/...` - Cursor автоматически откроет файл на нужной строке.

### Вариант 2: Смотреть логи docker-compose в терминале

Если нужно оставить Django в docker-compose:

1. **В отдельном терминале** (или новой вкладке терминала):
   ```bash
   cd docker
   docker-compose -f docker-compose.yml -f docker-compose.dev.yml logs -f web
   ```

2. **Пути в логах будут кликабельны** - Cursor автоматически распознает `/app/...`

## Почему это работает

- Cursor автоматически распознает пути к файлам в терминале
- Пути вида `/app/...` внутри контейнера маппятся на локальные файлы
- Клик по пути открывает файл на нужной строке

**Никаких дополнительных настроек не требуется!**
